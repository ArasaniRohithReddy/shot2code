# Product

## Register

product

## Users

Developers, designers, product builders, and learners who want to turn screenshots,
recordings, URLs, written briefs, or existing source into editable frontend code.
They work in a local desktop or browser workspace and need to compare model outputs,
refine a chosen result through conversation, inspect generated files, and export a
working project without surrendering control of credentials or source files.

## Product Purpose

shot2code shortens the path from a visual or written reference to working,
understandable frontend code. Success means users can connect the provider and tools
they choose, generate useful alternatives, preserve a clear project history, safely
iterate on real files, and understand every external capability or permission used
during a run.

## Brand Personality

Precise, capable, trustworthy, creative, bold, and energetic. The product should feel
like an expert tool that encourages experimentation without hiding risk, cost, or
automation behind vague language.

## Anti-references

- Generic AI or SaaS interfaces that feel interchangeable.
- Cluttered enterprise dashboards that make the primary task hard to find.
- Hidden automation, implicit permissions, or tools that activate without consent.
- Decorative motion that slows down work or obscures state.

## Design Principles

1. Keep the active creation and editing workflow visible; supporting controls should
   stay close without overwhelming it.
2. Make model, tool, cost, network, and write-access boundaries explicit before a run.
3. Preserve continuity: edits should read as a conversation, while History remains
   the durable version and branch record.
4. Prefer reversible, reviewed actions over silent installation or broad permission.
5. Balance expert capability with approachable defaults and actionable error states.

## Accessibility & Inclusion

Target WCAG 2.2 AA throughout the desktop and browser UI. Preserve complete keyboard
operation, visible focus, readable contrast, screen-reader semantics, reduced-motion
behavior, responsive reflow, and clear non-color status cues. Apply additional
best-effort accommodations when a platform or embedded provider surface limits full
conformance.
